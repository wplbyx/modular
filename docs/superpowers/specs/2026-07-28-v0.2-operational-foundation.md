# v0.2 Operational Foundation

## Scope

This specification defines the process bootstrap and transport contracts used
by modular v0.2 projects. It does not prescribe business layers. `cmd` remains
the only composition root; generated framework files expose seams but do not
own business decisions.

## Process Bootstrap Contract

Every generated process follows this order:

1. `config.NewRoot` loads and validates process configuration.
2. `cmd/<process>/policy.go` creates `log.LoggerManager` from `cfg.Logging`.
3. The process installs `log.SetDefault(loggerManager.Logger())`.
4. `cmd/<process>/policy.go` creates one `transport.Policy` from that logger.
5. `cmd` constructs Resources and Endpoints, injects the policy, and creates
   `app.NewApplication(ctx, cfg, logger, ...)`.
6. Application runs its established resource/endpoint lifecycle. Logger close
   happens after Application returns and drains accepted records.

Configuration is therefore always initialized first and logging second. A
Telemetry resource may attach an OTLP log sink only during `Resource.Setup`;
it never forces telemetry initialization ahead of the logger.

`cmd/<process>/framework.gen.go` is managed. `cmd/<process>/policy.go` is
scaffold-once and is where a project replaces logging outputs, propagation
policy, tracing, access logging, or adaptive protection.

## Logging and Event Queue Contract

- `log.Logger` requires `context.Context` for every event. Context supplies
  request ID, language, trace ID, and span ID; callers use
  `context.Background()` only when no request context exists.
- `LoggerManager` can dispatch asynchronously. Debug/info/warn records may be
  dropped on a full queue; error records wait only for the configured bounded
  timeout and then use a synchronous stderr fallback. `Sync` and `Close` use a
  barrier and drain records already accepted by the queue.
- Logger and EventBus store queued data directly in
  `github.com/cyub/ringbuffer.MpscRingBuffer`. The modular repository must not
  implement, fork, wrap as a new RingMPSC type, or copy a lock-free ring
  algorithm. Wakeup channels contain only signals, never queued log/event data.
- `eventbus.Bus` is a `core.Resource`, has one ordered consumer, rejects new
  events during close, and drains accepted events. It snapshots metadata/span
  context at publish time. Payload ownership remains with the publisher.

## Metadata and Transport Contract

`packages/metadata` stores immutable, scoped values in Context:

- Global values (`x-request-id`, `x-language`, `x-md-global-*`) may cross a
  process boundary.
- Local values (`x-md-local-*`) remain inside the process.
- Authorization, cookies, and other sensitive values are denied unless an
  explicit propagator allowlist permits them.
- Extraction enforces key-count, key-size, and total-size limits and creates a
  request ID when absent.

The default HTTP and gRPC server chain is:

```text
Recovery/Error boundary -> Metadata/Request ID -> OpenTelemetry
-> Access log -> Adaptive BBR/SRE protection -> User middleware/handler
```

The default HTTP/gRPC clients inject Metadata, create OpenTelemetry client
spans, log completion, and observe adaptive protection. Only server failures
(network failures or 5xx / gRPC infrastructure codes) count against breakers;
caller cancellation and 4xx do not. Kafka, Redis Stream, and RocketMQ carry
headers. MQTT v3 and Redis Pub/Sub channels have no header carrier, so they do
not claim cross-process metadata propagation.

The adaptive algorithms are supplied by Kratos Aegis BBR and SRE breaker. The
library owns adaptation internals; modular owns operation naming, bounded
per-operation breaker allocation, and boundary error mapping.

## Business Layer Contract

Framework generation is application-first. A simple CRUD/MVC feature starts
with app ports and adapters; it must not generate an empty domain, repository,
event handler, DTO, or fake success response. Introduce a domain module only
when aggregates, invariants, policies, transactions, or domain services remove
real complexity. Stable reasons remain language-neutral in business/domain
code; localization happens at HTTP/gRPC error boundaries.

## Generation and Verification Contract

The manifest records only managed-file ownership, generated hash, template
version, and minimal feature provenance. It is not an architecture decision
document. Managed files update only when their recorded hash still matches;
scaffold-once files are preserved; untracked collisions stop the transaction.

The CLI must provide `--dry-run`, `--diff`, idempotent `sync`, safe `prune`,
strict `doctor`, and transactional rollback. Framework completion requires
self-check, strict doctor, placeholder scan, and build. Contract and complete
phases add buf generation, tests, race tests, vet, and business-marker checks
as defined by the project skill.
