# modular v0.2 Architecture

## Intent

v0.2 keeps `Application`, `core.Endpoint`, `core.Resource`, and `core.ServiceNode` as the main architecture. It deepens the resource module, removes hidden infrastructure state, and adds small operational modules without turning Application into a framework container.

## Resource seam

`core.ManagedResource[T]` owns setup, close, readiness, synchronization, and typed value access behind two small interfaces:

```go
type Resource interface {
    Name() string
    Setup(context.Context) error
    Close(context.Context) error
}

type Provider[T any] interface {
    Value() (T, error)
}
```

Application sees only `Resource`. Repositories receive the typed `Provider[T]`. This keeps lifecycle policy local to core while preserving explicit dependency injection.

## Lifecycle

Application states are `new -> running -> stopping -> stopped`. Run is single-use. Close before Run transitions directly to stopped and does not touch resources or endpoints. Startup preparation and shutdown are serialized so a concurrent Close cannot race resource setup.

The existing ordering remains unchanged:

1. Resource Setup in FIFO order.
2. Register ServiceNode.
3. Endpoint Startup in parallel and blocking.
4. Endpoint Shutdown in parallel.
5. Unregister ServiceNode.
6. Resource Close in LIFO order.

## Infrastructure

- Bun, GORM, MongoDB, Redis, and Storage expose managed resources and no package-level connection globals.
- SQL configuration contains an explicit DSN. MongoDB has a separate configuration type.
- GORM dialect selection happens in cmd through optional dialect subpackages.
- SQLite uses a pure Go driver.
- Storage composition lives in `packages/infra/storage/resource` to avoid a parent/child import cycle.

## Operations

- `packages/health` is standard-library-only and aggregates structural `Checker` implementations.
- `/health` remains liveness. Optional readiness returns 200/503 and becomes the registered transport health path.
- Embedded configuration uses `config.WithConfigFS`.
- `buildinfo.Read(name, version)` has no application configuration global.
- The HTTP client follows `net/http` through a concrete Client and Do method, with bounded retry semantics.
- Process bootstrap is explicit: config is loaded first, logger is created second, and `cmd` owns policy/resource/endpoint composition.
- Logging and the local event bus use `github.com/cyub/ringbuffer.MpscRingBuffer` directly for queued records. modular adds lifecycle and wakeup policy only.
- Metadata is immutable and scoped; HTTP/gRPC and header-capable messaging transports propagate safe global values and OpenTelemetry trace context.
- Transport policy supplies recovery, metadata, tracing, access logging, and Aegis BBR/SRE protection by default while `cmd` can replace each decision.

## Deliberate exclusions

v0.2 does not add JWT/RBAC, sqlx/sqlc/pgx, Lambda adapters, a modular-owned ring-buffer algorithm, concurrent maps, custom cgroup metrics, or arbitrary Application lifecycle phases.
